# 契约生成与一致性校验

请按 `.codebuddy/rules/api-contract-first.mdc` 执行契约流水线，并**如实报告每一步结果**。

## 执行步骤

### 1. 后端产出 OpenAPI

- 触发后端构建，产出 `openapi.json`
- **若构建失败**：输出失败原因并停止，不要跳过、不要手工编造 openapi.json

### 2. 破坏性变更检测

- 与基线（`packages/api/openapi.baseline.json` 或上次提交版本）做 diff
- 检测项：**删字段、改类型、改必填性、改枚举取值、改路径**
- 若有破坏性变更：**列出明细并要求我确认**，不要自行继续

### 3. 前端生成

- 运行契约生成（`pnpm gen:api`，orval）
- 产出：`packages/api/src/generated/` 下的 types / schemas / endpoints / queries

### 4. 一致性校验

- 运行 `tsc --noEmit`，报告类型错误
- 检查 `git diff packages/api/src/generated` 是否为空 → **不为空说明生成产物未同步提交**
- **禁止手工修改 `packages/api/src/generated/**`** —— 若发现手改痕迹，明确指出并回滚

## 输出格式

```
## 契约流水线报告

### 1. OpenAPI 产出
✅ / ❌  <路径或失败原因>

### 2. 破坏性变更
✅ 无破坏性变更
或
⚠️ 检测到 N 项破坏性变更：
| # | 位置 | 变更 | 影响 |
|---|------|------|------|

### 3. 前端生成
✅ 生成 N 个文件
或
❌ 失败：<原因>

### 4. 类型校验
✅ tsc 通过
或
❌ N 处类型错误（见下）

### 5. 生成产物同步
✅ 无未提交变更
或
⚠️ 存在未提交变更，需先提交

### 下一步
<明确列出需要我做的事>
```

## 约束

- **每一步都要真实执行并报告真实结果**，不要假装成功
- 构建或生成失败时**直接报告失败**，不要绕过、不要手工构造产物
- 检测到破坏性变更时必须**停下来问我**，不得自行决定
- 不要修改后端源码"让生成通过" —— 契约问题应从接口设计层面解决
- 报告最后必须明确：**这次契约变更需要前端配合改哪些地方**
