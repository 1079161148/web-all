# 新增权限点

权限码：**$1**
说明：**$2**

> 权限码格式必须为 `{context}:{resource}:{action}` 三段式，如 `iam:user:add`。
> 若 $1 不符合该格式，**先纠正我**，不要直接照做。

权限只做一半是本项目最常见的返工原因（前端能点但接口不拦、或接口拦了但菜单没配）。请**四处同步**。

## 第 1 步：确认现状（先查再改）

1. 该权限码是否已存在（搜索后端注解 + 菜单初始化脚本 + 前端常量）
2. 归属哪个限界上下文与资源
3. 该资源当前已有哪些权限码（保持命名一致）

## 第 2 步：四处同步

### ① 后端接口注解

```java
@PreAuthorize("@ps.hasPermission(\"$1\")")
```

- 加在**对应的写 / 敏感读接口**上
- 只加在真正需要该权限的方法上，不要一把加到 Controller 类上（会导致权限过粗）
- 若接口涉及数据范围，同时确认是否需要 `@DataScope`

### ② 权限码常量

- 在项目既有的权限码常量类 / 枚举中登记，**禁止在业务代码里散落字符串字面量**
- 若采用枚举方式，确保与 `@PreAuthorize` 的 SpEL 取值路径一致

### ③ 菜单 / 权限记录

- 若是**按钮级**权限：在 `iam_menu` 的初始化数据（Flyway `R__` 或 `afterMigrate.sql`）中追加按钮类型记录，`perms` 字段填该权限码
- 若是**菜单级**：补菜单记录（路径、组件、图标、排序）
- **不要修改已上线的迁移脚本** —— 新增 `V` 脚本或更新可重复执行的 `R__` 脚本
- 同步更新角色-菜单关联的默认授权（如超管角色）

### ④ 前端使用

```vue
<!-- 按钮显隐 -->
<n-button v-permission="'$1'">导出</n-button>

<!-- 或在 ProTable 列 / 行操作中声明 -->
{ key: 'export', label: '导出', permission: '$1' }
```

- 前端使用 `v-permission` 指令，**不要用 `v-if` 手写判断**
- 若在 ProTable 的 `columns` / `rowActions` 中，用 `permission` 字段声明，组件内部处理

## 第 3 步：验证清单

输出以下确认结果：

| # | 检查项 | 状态 |
|---|---|---|
| 1 | 后端接口已加 `@PreAuthorize` | ✅/❌ |
| 2 | 权限码常量已登记 | ✅/❌ |
| 3 | 菜单 / 按钮记录已补 | ✅/❌ |
| 4 | 前端已用 `v-permission` / `permission` 声明 | ✅/❌ |
| 5 | **后端独立鉴权已验证**（前端隐藏不等于后端拦截） | ✅/❌ |
| 6 | 已补权限相关的集成测试 | ✅/❌ |

## 约束

- **不要只改其中一处就宣布完成** —— 必须四处齐全
- 不要修改已上线的 Flyway `V` 脚本
- 不要自创权限码风格（必须 `context:resource:action`）
- 后端必须真实鉴权，**前端隐藏不算权限控制**
- 涉及权限的变更属于需要评审的范围，完成后提示我需要评审
