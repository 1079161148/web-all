# 代码评审

请读取并应用 `.codebuddy/rules/code-review-checklist.mdc` 的完整清单，对以下内容进行评审：

$ARGUMENTS

若未指定路径，则评审当前工作区的全部未提交改动（`git diff` 与未跟踪文件）。

## 评审要求

1. **先判断复杂度级别**（L1 / L2 / L3）—— L3（核心域）必须更严格，且需标注"需架构组评审"
2. **只报真实问题**，不要报风格偏好或无依据的"建议"
3. 每个问题必须给出**具体文件 + 行号 + 修复方向**
4. 命中 §1 架构红线 或 §2 多租户任一项 → **直接判定打回**

## 覆盖维度

| 维度 | 重点 |
|---|---|
| 架构红线 | 领域层框架污染、依赖方向、三层对象分离、AppService 中的业务 if |
| 多租户 | `tenant_id`、唯一索引、缓存 Key、异步上下文传递、按 ID 查询 |
| 权限与安全 | 写接口权限注解、后端兜底、字段脱敏（含导出/日志）、参数校验、SQL 拼接 |
| 数据库 | Flyway 新增脚本、通用字段、字段注释、索引规范、大表分批 |
| 性能 | N+1、无 LIMIT 查询、大字段、表格内组件、依赖体积 |
| 测试与文档 | 核心域单测、多租户集成测试、OpenAPI 注解、生成产物已提交、ADR |
| 代码质量 | 命名、异常处理、日志、注释、死代码、`any` |
| 前端专项 | UI 库直引、手写类型、服务端数据入 Pinia、硬编码样式、状态矩阵完整性 |

## 输出格式

```
## 代码评审报告

复杂度级别：L2 标准模式
评审范围：<文件列表>
结论：🟡 有条件通过

### 🔴 必须修复（阻塞合并）
| # | 文件:行 | 问题 | 对应清单项 | 修复方向 |
|---|---------|------|-----------|----------|

### 🟡 建议修复
| # | 文件:行 | 问题 | 修复方向 |
|---|---------|------|----------|

### ✅ 通过项
- 架构依赖方向正确
- ...

### 说明
<无法判断的项，明确说明，不要猜>
```

## 约束

- **只读评审，不要修改任何文件**
- 不要因为"代码看起来还行"就跳过清单项 —— 逐项过
- 不确定的地方明确标注"无法确认"，不要编造违规
- 若确实没有问题，直接说"未发现问题"并列出已检查的维度
