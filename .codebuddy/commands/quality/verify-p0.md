# P0 技术验证

> **这 8 项是整个架构能否成立的前提。** 任何一项不通过都需要调整方案，不能带着未知风险继续开发。
> 参考：`后台管理系统功能设计方案.md` 的「二十一、P0 验证清单」。

验证范围：$ARGUMENTS（为空则全部执行）

## 验证项

| # | 验证项 | 不通过的应对 |

## 各验证项要求

### 1. MyBatis-Plus × Spring Boot 4

- 编写最小可运行示例：一个表 + Mapper + 分页查询
- 验证：自动配置是否生效、分页插件是否正常、逻辑删除与自动填充是否工作
- **记录实际可用的依赖坐标与版本号**

### 2. vxe-table × Naive UI 主题桥接

- 用 Design Token 值适配 vxe-table 主题变量
- 验证：暗色模式切换一致性、表格边框/表头/斑马纹/悬浮态与 Naive 组件视觉是否统一
- **记录需要覆盖的 CSS 变量数量与工作量估算**

### 3. Naive UI CSS-in-JS 开销 ⚠️ 最关键

编写基准测试页，对三种方案在 **1 万行 × 10 列** 下测量：

| 方案 | 首渲染耗时 | 滚动帧率 | 样式节点数 |
|---|---|---|---|
| `n-data-table` | | | |
| `vxe-table` | | | |
| `vxe-table` + 自绘单元格 | | | |

**用数据决定是否需要静态样式提取，不靠猜。**

### 4. form-create 兼容性

- 验证 `@form-create/naive-ui` 在 Vue 3.5 + Naive 2.44 下可用
- 检查最近提交时间与 issue 响应情况
- 验证设计器产物（rule JSON）可正确回显与渲染

### 5. Vite 8 插件兼容

逐项验证项目所需插件在 Rolldown 引擎下可用：compression2 / visualizer / unplugin-* / UnoCSS / Sentry / svg 等。**列出可用与不可用清单。**

### 6. 虚拟线程 + 连接池

- 开启虚拟线程，压测并发查询
- **验证 HikariCP 连接池上限是否被打爆**
- 验证虚拟线程下租户上下文（`ThreadLocal` vs `ScopedValue`）是否正确传递

### 7. Histoire

- 检查项目活跃度（最近提交、issue 响应、Vue 3.5 兼容）
- 判断是否满足 Pro 组件工作台需求

### 8. Oxlint 规则覆盖

- 验证 Vue / TypeScript / 架构约束（禁止 import）规则能否表达
- 特别是 `no-restricted-imports`（禁止 `apps/**` import `naive-ui`）
- **若无法覆盖，明确列出需要保留 ESLint 的规则集**

## 约束

- **每一项都要真实执行**，用真实数据，不要凭记忆或推测下结论
- 不确定/未验证的项**必须明确标注**，不要为了让报告好看而假装通过
- 验证过程中的临时脚本与测试文件，**完成后清理**（或放在 `examples/` 并说明保留理由）
- 若某项被阻塞（缺环境、缺依赖），**直接说明阻塞原因**，不要跳过
